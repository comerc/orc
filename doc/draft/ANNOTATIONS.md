- `> 23_14-43-00`: Существующим инструментам (Windmill, LangGraph) не хватает «продуктового клея» для бизнеса.
- `> 23_14-47-06`: n8n слишком хрупок для критических процессов, а Temporal слишком сложен — нужен Control Plane с надежностью SaaS.

- `> 25_15-20-14`: Техническое ядро должно делать снепшот состояния после каждого шага LLM (Snapshot-per-step).
- `> 25_15-20-14 (2)`: Главные фичи для продажи: Observability (отладка промитов), контроль токенов и позиционирование как «Страховка для ИИ».
- `> 25_15-48-04`: Анализ конкурентов: Temporal (инфраструктура), n8n/Zapier (визуал), Windmill (ближайший аналог для девов).
- `> 25_15-48-05`: Почему такого UI еще нет: сложность сериализации состояния, ад с версионированием процессов и цена хранения.

## PART-04.md: Углубление в Архитектуру

- `> 28_14-48-59`: Inngest сложно встроить в один бинарник (embedded), так как он требует отдельного сервера управления.
- `> 28_14-48-59 (2)`: Альтернативы для "одного бинарника": Temporalite, самописный движок на SQLite или Ebu.
- `> 28_14-53-34`: Ebu (Erlang на Go) — библиотека акторов для создания легковесного "Go-Phoenix".
- `> 28_14-53-34 (2)`: Стек на Ebu: Core (Go) + Orch (Ebu) + State (SQLite) + Exec (Wasm) — мощно, но сложно.
- `> 28_14-56-51`: Ebu + ElectricSQL = Active Replication (синхронизация стейта через БД) для "бессмертия".
- `> 28_14-56-51 (2)`: Плюсы: offline-first, стриминг в UI; Минусы: конфликты версий и рост объема данных.
- `> 28_15-01-34`: Durable Streams — это примитив (лог событий), который можно реализовать на Postgres/Redis без Electric.
- `> 28_15-01-34 (2)`: Реализация на Go: легкий Event Sourcing, идеален для UI, но требует ручной обработки идемпотентности.
- `> 28_15-06-06`: Паттерн Saga: Event-Driven (череда событий) или Orchestrated (центральный координатор).
- `> 28_15-06-06 (2)`: Компоненты Саги: RequestID (защита от дублей), журнал компенсаций, таймауты; Ebu подходит для "State-as-Stream".
- `> 28_15-14-06`: Hatchet (Go) — самый прагматичный выбор фундамента: нативный Go, низкая задержка (gRPC), готовый UI.
- `> 28_15-14-06 (2)`: Hatchet легко селф-хостить (один бинарник + PG) и он поддерживает Саги "из коробки" (шаги on_failure).
- `> 28_15-17-55`: Стратегия: Hatchet как ядро (Engine) + фичи Windmill (UI, запуск скриптов на лету через Docker/Wasm).
- `> 28_15-17-56`: Стек MVP: Core (Hatchet) + API (Go) + Runtime (Wazero/Docker) + Frontend (React Flow).
- `> 28_15-29-33`: Зачем Durable Streams: решение проблемы "моргающего интернета" и потери истории генерации.
- `> 28_15-29-33 (2)`: Разделение: Hatchet гарантирует выполнение на сервере, Streams гарантируют доставку клиенту.
- `> 28_15-56-23`: Позиционирование Hatchet: общий оркестратор (Queue + DAG), заменяющий перегруженные AI-фреймворки.
- `> 28_15-58-11`: Hatchet + Windmill UI = идеальный Fit; Hatchet дает базу, мы добавляем AI-специфику (токены, чаты).
- `> 28_15-58-11 (2)`: Саги в Hatchet реализуются через визуализацию связей DAG и узлов компенсации.

- `> 29_01-25-09`: Архитектура изоляции: Hatchet -> Go Worker -> typescript-go (валидация) -> nsjail -> Deno.
- `> 29_01-26-42`: Правильный Runner: Валидация, подготовка RootFS (OverlayFS), запуск nsjail; лучше чем GitLab Runner.
- `> 29_01-26-42 (2)`: Пример кода воркера на Go: транспиляция, запуск команды, возврат результата.
- `> 29_01-10-26`: Каноничная реализация: `net/http` (прием) -> `ts-go` (проверка) -> `os/exec` (nsjail+Deno).
- `> 29_01-12-59`: Три альтернативы: Wasm/Wazero (чистый Go, быстро), Firecracker (макс. защита), QuickJS (легкий).
- `> 29_01-12-59 (2)`: Fly.io использует Firecracker; Wazero рекомендован для чистоты экосистемы Go.
- `> 29_01-34-48`: Как у гигантов: Vercel (V8 Isolates), Supabase (Deno/Go процессы).
- `> 29_01-34-48 (2)`: AWS использует Firecracker (MicroVM) для полной изоляции уровня железа.
- `> 29_01-35-50`: Статус OASF: рабочий стандарт описания агентов, полезен в связке с ACP.
- `> 29_01-48-45`: Уровни доверия (Trust Levels): профили nsjail (Zero Trust vs Trusted) и флаги Deno.
- `> 29_01-48-45 (2)`: Реализация: разные очереди в Hatchet (secure/perf) и Unix Socket для доступа к БД.
- `> 29_01-51-21`: Полиглот-рантайм: единый контейнер с профилями nsjail для TS (Deno), Python (MicroPython), Go (Binary).
- `> 29_01-51-21 (2)`: Bridge: единый Unix Socket + JSON-RPC для общения любого языка с движком.
- `> 29_02-00-40`: Bun vs Deno: Bun быстрее, но требует небезопасных разрешений (seccomp) для работы.
- `> 29_02-00-40 (2)`: Bun не имеет встроенной системы прав; Deno 2 безопаснее для DE.
- `> 29_02-10-12`: Почему одного V8 мало: Prompt Injection может вызвать JIT-баги и побег из песочницы.
- `> 29_02-10-12 (2)`: Defense in Depth: nsjail обязателен как вторая стена за V8.
- `> 29_02-11-14`: Роль `typescript-go`: пре-флайт валидация и статический анализ безопасности до запуска.
- `> 29_02-11-14 (2)`: Пайплайн: User -> Engine (ts-go check) -> Hatchet -> Worker (nsjail+Deno).

## PART-06.md: Стратегия и Продукты

- `> 30_12-23-47 (2)`: Выбор: Mastra для встройки в приложение, Windmill для внутренних тулов.
