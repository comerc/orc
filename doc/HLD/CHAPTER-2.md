# Глава 2. Паттерны Надежности в мире ИИ

## 2.1. Транзакции и Саги: Укрощение хаоса LLM

Классические ACID-транзакции (commit/rollback) неприменимы в мире ИИ. Нельзя «откатить» генерацию текста или вызов внешнего API (отправленное письмо). Единственный способ обеспечить целостность бизнес-процесса — это паттерн **Saga** (Сага).

### Проблема LLM

ИИ-агент — это вероятностная сущность.

- Он может сгенерировать правильный ответ.
- Он может сгенерировать мусор.
- Он может зависнуть.
  Если агент на шаге 3 ошибся, нам нужно не просто «упасть с ошибкой», а запустить цепочку **компенсирующих действий** (например, извиниться перед пользователем, отменить бронь в календаре, вернуть токены на баланс).

### Решение: Orchestrated Saga (Код с компенсациями)

В архитектуре Hatchet саги часто рисуются как ветвления на графе («Если ошибка -> иди в ветку Б»). Это делает граф гигантским и нечитаемым.
В нашей архитектуре (Restate-style) мы реализуем Сагу через **Saga Container** в SDK.

**Как это выглядит в коде агента (Go/TS):**

```go
func RunAgent(ctx Context) {
    saga := NewSaga()

    // Шаг 1: Зарезервировать ресурсы
    result, err := ctx.Run("reserve", func() { ... })
    if err != nil { return saga.Compensate() } // Автоматический откат
    saga.AddCompensation(func() { ctx.Run("release_resources", ...) })

    // Шаг 2: Вызов LLM
    response, err := ctx.Run("llm_generate", func() { ... })
    if err != nil {
        // Если LLM упала, мы не просто выходим, а запускаем компенсации в обратном порядке
        return saga.Compensate()
    }
}
```

**Преимущество:** Разработчик пишет линейный код («счастливый путь»), а обработку «грязной работы» по откатам берет на себя движок. Движок гарантирует, что каждая компенсирующая функция будет выполнена, даже если сервер упадет посередине процесса отката.

## 2.2. Точка входа: От Ingress SDK к AI Gateway

Как запустить процесс? В классическом Restate используется Ingress SDK — специальный клиент, который стучится в движок. Для ИИ-платформы этого мало. Нам нужен полноценный **AI Gateway**.

### Эволюция входа

- **Ingress SDK (Restate):** Просто обеспечивает идемпотентность запуска. «Не запускай процесс №123 дважды».
- **AI Gateway (Наш продукт):** Это умный шлюз перед запуском воркфлоу.

### Функции Gateway

1.  **Semantic Caching:** Перед тем как будить агента и тратить деньги, Gateway проверяет: «Мы уже отвечали на похожий вопрос?». Если да — ответ отдается мгновенно из кэша (Redis/Vector DB).
2.  **Rate Limiting & Quotas:** «Отдел маркетинга исчерпал бюджет на GPT-4». Gateway блокирует запрос еще до старта Durable-процесса.
3.  **Model Routing:** Gateway может на лету подменить модель. Если GPT-4 недоступна, он направит запрос в Claude 3.5 или локальную Llama, передав этот параметр в контекст агента.

**Итог:** Мы не просто «запускаем скрипт», мы управляем потоком запросов. Это критически важная фича для продажи Enterprise-клиентам.

## 2.3. Durable Streams: Разделение ответственности

В ИИ-приложениях есть фундаментальный конфликт между надежностью бэкенда и ожиданиями пользователя.

- **Бэкенд:** «Я буду думать 5 минут, чтобы дать лучший ответ».
- **Пользователь:** «Я хочу видеть хоть что-то прямо сейчас».

### Проблема WebSocket

Обычный стриминг токенов (через WebSocket) хрупок. Если у пользователя мигнул Wi-Fi, соединение рвется, и он видит ошибку сети, хотя на сервере агент продолжает работать и тратить деньги.

### Решение: Архитектура Durable Streams

Мы разделяем процесс на два независимых потока:

1.  **Execution Stream (Server-side):** Агент работает и пишет свои «мысли» (tokens, logs, reasoning) в надежный лог (append-only log в Postgres/Redis). Ему все равно, слушает ли его кто-то.
2.  **Delivery Stream (Client-side):** UI клиента подключается к этому логу.
    - Если связь есть — он читает в реальном времени.
    - Если связь пропала — клиент запоминает последний полученный `offset` (смещение).
    - Когда связь вернулась — клиент просит: «Дай мне всё, что случилось после offset X».

**Результат:** Пользователь получает **Gap-less UX** (бесшовный опыт). Он может закрыть вкладку, уйти пить кофе, открыть с телефона — и увидеть полную историю генерации без пробелов. Это и есть уровень качества, который отличает профессиональный инструмент от поделки на коленке.
