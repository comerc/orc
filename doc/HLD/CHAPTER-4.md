# Глава 4. Интерфейс Платформы (UI/UX): Уроки Windmill

## 4.1. Почему интерфейс важен?

Restate — это код. Для инженера это прекрасно, но для бизнеса это «черный ящик». Windmill доказал, что **визуализация кода** делает платформу доступной для широкого круга пользователей. Наша задача — натянуть этот UX на наш Go-движок.

---

## 4.2. Наследие Windmill: Что мы забираем?

### Flow Builder (Визуальный редактор)

Вместо того чтобы заставлять пользователя писать YAML или JSON вручную, мы даем ему холст (Canvas).

- **Реализация:** React Flow + Go-бэкенд.
- **Как это работает:** Каждый узел на графе — это функция. Стрелка — это передача данных.
- **Секрет:** Под капотом этот граф компилируется в Go-структуры, которые исполняет наш Durable-движок. Визуал — это просто удобный способ конфигурации.

### Auto-forms (Авто-формы)

Это киллер-фича Windmill.

- **Суть:** Если функция принимает аргументы `(email: string, count: int)`, UI автоматически генерирует красивую форму с валидацией.
- **Для ИИ:** Это позволяет менеджеру запустить сложного агента, просто заполнив поля «Тема письма» и «Количество вариантов», не видя кода.

### Scripts-as-a-Service (Скрипты "на лету")

Возможность открыть встроенный редактор (Monaco Editor), написать 10 строк на Python, нажать «Save» и сразу использовать этот скрипт как узел в графе. Никакого CI/CD, никаких git push. Это ускоряет разработку в разы.

## 4.3. Специфика AI: Новые требования к UI

### Чат-режим и Debugger

Для ИИ недостаточно просто видеть «Успех/Ошибка».

- **Streaming UI:** Интерфейс должен уметь отображать текст по мере генерации (через наши Durable Streams).
- **Reasoning Tree:** Визуализация «дерева мыслей» агента. Если агент пробовал три варианта решения и выбрал один, пользователь должен видеть эти ветки.

### Human-in-the-loop (Узлы Одобрения)

Это то, чего нет в чистом Restate.

- **Approval Node:** Специальный тип шага. Когда процесс доходит до него, он **приостанавливается** (Durable Sleep) и отправляет уведомление.
- **Интерфейс:** В панели управления появляется задача «Требуется действие». Менеджер может просмотреть сгенерированный агентом черновик, поправить его прямо в UI и нажать «Approve». Только после этого процесс продолжится.

## 4.4. Итог по UI

Мы строим не просто «админку», а **Рабочее место оператора ИИ**.

1.  **Для разработчика:** Flow Builder и IDE для скриптов.
2.  **Для менеджера:** Auto-forms и дашборд задач на одобрение.
3.  **Для аудитора:** Полная история и «машина времени» (Time Machine) для разбора полетов.
