# Глава 4. Интерфейс Платформы (UI/UX): Уроки Windmill

## 4.1. Почему интерфейс важен?

Restate — это движок Durable Execution, основной доступ к которому идёт через код и инженерный UI для отладки и наблюдения. Для разработчика это прекрасно, но для бизнеса он остаётся фактически «чёрным ящиком». Windmill показывает противоположный подход: **визуализация кода** и автогенерация UI делают платформу доступной широкому кругу пользователей. Наша задача — перенести похожий UX на наш Go-движок, сохраняя его производительность и гибкость.

---

## 4.2. Наследие Windmill: Что мы забираем?

### Flow Builder (Визуальный редактор)

Вместо того чтобы заставлять пользователя писать YAML или JSON вручную, мы даём ему холст (Canvas).

- **Как это устроено в Windmill:** Визуальный редактор реализован поверх Svelte-библиотеки Svelvet (node-based canvas), а логика потоков хранится в формате OpenFlow (JSON/YAML), который затем исполняет Rust-движок. Потоки можно экспортировать и импортировать в этом формате.
- **Реализация (у нас):** Canvas на React Flow + наш Go-бэкенд. Концептуально это аналог подхода Windmill (узлы и рёбра), но реализованный на нашем стеке.
- **Как мы делаем у себя:** Граф на Canvas сохраняется в нашем внутреннем формате (Go-структуры), концептуально близком к OpenFlow, который затем исполняет наш Go-based durable-движок. Визуал — это просто удобный способ конфигурации.

### Auto-forms (Авто-формы)

Это киллер-фича Windmill.

- **Суть:** Если функция принимает аргументы `(email: string, count: int)`, UI автоматически генерирует красивую форму с валидацией на основе JSON Schema, выведенной из сигнатуры. Пользователь не работает с JSON Schema напрямую — всё настраивается через визуальный интерфейс.
- **Для ИИ:** Это позволяет менеджеру запустить сложного агента, просто заполнив поля «Тема письма» и «Количество вариантов», не видя кода.

### Scripts-as-a-Service (Скрипты "на лету")

Возможность открыть встроенный редактор (Monaco Editor), написать 10 строк на Python, нажать «Save» и сразу использовать этот скрипт как узел в графе. Можно просто сохранить скрипт и сразу использовать его в потоках и приложениях, без обязательного CI/CD или git push. При желании git-флоу и CI/CD легко подключаются, но они не являются блокирующим шагом для запуска.

## 4.3. Специфика AI: Новые требования к UI

### Чат-режим и Debugger

Для ИИ недостаточно просто видеть «Успех/Ошибка».

- **Streaming UI:** Как и в Windmill, интерфейс должен уметь стримить ответы агента в реальном времени по SSE. В дальнейшем мы планируем реализовать собственный механизм durable-streams для возобновляемых потоков поверх нашего Go-движка.
- **Reasoning Tree (наша эксклюзивная надстройка):** Windmill уже визуализирует вызовы инструментов (tool calls) и стримит ход работы агента, но не строит отдельное дерево всех альтернативных веток рассуждений. Мы добавляем режим Reasoning Tree, который отображает путь агента по веткам решений как дерево. Если агент пробовал три варианта решения и выбрал один, оператор увидит все три ветки и их исход. Эта функция отсутствует в Windmill и реализуется нами как надстройка над durable-движком.

### Human-in-the-loop (Узлы Одобрения)

Это то, чего нет в чистом Restate.

- **Approval Node:** Специальный тип шага. Когда процесс доходит до него, он **приостанавливается** (suspend / долговременная пауза без лимитов по времени) и отправляет уведомление.
- **Интерфейс:** В панели управления появляется задача «Требуется действие». Менеджер может просмотреть сгенерированный агентом черновик, поправить его прямо в UI и нажать «Approve». Только после этого процесс продолжится.

## 4.4. Итог по UI

Мы строим не просто «админку», а **Рабочее место оператора ИИ**.

1.  **Для разработчика:** Flow Builder и IDE для скриптов.
2.  **Для менеджера:** Auto-forms и дашборд задач на одобрение.
3.  **Для аудитора:** Полная история запусков и возможность детально разобрать каждый шаг.

---

**Примечание:** В этой главе мы опираемся на UX-паттерны Windmill, но реализуем их поверх собственного Go-движка и добавляем свои функции, такие как Reasoning Tree. Windmill использует бэкенд на Rust, OpenFlow для описания потоков, Svelvet для визуального редактора, Monaco Editor для кода, SSE-стриминг для AI-агентов и approval-шаги для human-in-the-loop. Мы адаптируем эти решения под нашу архитектуру, реализуя аналогичную логику на Go и React Flow, а также добавляем собственные расширения, отсутствующие в оригинальном продукте.
